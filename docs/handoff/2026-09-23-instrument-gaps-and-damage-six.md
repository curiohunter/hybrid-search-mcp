## 2. 다음 작업 — damage 6 의 원인

### 무엇이 새는가

2026-09-12 주인 결정: 실물(브랜치·커밋·파일·워크트리)이 하나도 겹치지 않으면 supersession
금지. 코드는 `src/hybrid_search/memory/supersession.py` 의 `_artifacts` → `_disjoint_work`
(매핑 루프 `if _disjoint_work(work[i], work[j]): continue`).

그런데 홀드아웃 17건 중 6건이 그 모양으로 새로 생겼다. 판정 사유는 거의 전부 "다른
워크트리·다른 브랜치의 같은 운영 요청"(머지/워크트리 정리/배포 류).

### 가설 (검증 전 — 먼저 확인할 것)

`_disjoint_work` 는 **교집합이 비었을 때만** 발동한다. 겹치는 것이 하나라도 있으면 통과한다.
운영 요청 턴은 자기 일과 무관한 실물을 공통으로 언급한다:

1. **frontmatter 의 기록된 정체.** `branch:`/`head:` 가 있으면 스캔 대신 그것만 쓴다.
   두 턴이 모두 메인 폴더에서 끝났으면 둘 다 `branch: main` — 무조건 겹친다.
2. **다른 세션의 워크트리.** "남은 워크트리는 다른 세션 것이라 안 건드렸다" 류 문장이
   같은 이웃 워크트리를 양쪽에서 언급한다.
3. **공유 파일.** `CLAUDE.md`, 자동 생성 파일 등 "건드리지 않았다"고 보고하는 파일.

즉 "언급"과 "작업 대상"이 구분되지 않는다. 1번이 맞다면 기록된 정체 경로가 스캔
경로보다 **더 나쁘다** — 정확하라고 만든 경로가 가장 흔한 브랜치명으로 모든 것을 겹친다.

### 절차

1. **해부.** damage 6건(라벨 파일에서 `judge: llm, verdict: damage`)마다 양쪽의
   `_artifacts` 를 출력하고 교집합을 본다. 가설 1~3 중 무엇인지 건별로 적는다.
   읽기 전용, 스냅샷에서.
2. **사전 등록** (연구 문서 새 절에, 측정 전에):
   - 성공: 라벨된 damage 6 → 0 (재계산된 맵이 그 쌍을 더는 잇지 않음)
   - 회귀 금지: legitimate 라벨(사람 15 · 모델 11, 후계자가 남아 있는 것) 중 **연결이
     끊기는 것 0** — 막대를 조이면 진짜 갱신도 끊긴다. 이것이 이 작업의 진짜 제약이다
   - 회귀 금지: Set A mrr ≥ 0.5905 · top3 ≥ 0.70, Set B, 코드축(0.92·0.77·0.16)
   - 보고만: 맵 항목 수 변화
3. **수정 후보** (해부 결과에 따라 고를 것):
   - `main`/`master` 같은 기본 브랜치명은 정체로 치지 않는다
   - "안 건드렸다/다른 세션 것" 문맥의 언급은 실물에서 뺀다 — 어휘 규칙이라 취약하다
   - 교집합 대신 **작업 대상 실물**(기록된 `touched:`)이 겹치는지만 본다
4. **측정.** `python benchmarks/recompute_supersession.py --config $SNAP/config.toml` 로
   스냅샷 안에서만 맵을 재계산(재인덱싱 없음) → 감사 + Set A/B + 코드축.

### 함정

- 스냅샷의 맵을 바꾼 채 두지 말 것. 측정이 끝나면 `recompute_supersession.py` 를 원래
  코드로 한 번 더 돌리거나 스냅샷을 다시 얼린다.
- 라벨 파일은 레포 밖(`~/.hybrid-search/benchmarks/`)이다. 사유 문장이 실제 턴을
  식별하므로 레포·문서에 옮기지 말 것.
- 이번 가설은 코드 읽기에서 나왔지 데이터로 확인하지 않았다. 1번 해부 전에 고치지 말 것.
