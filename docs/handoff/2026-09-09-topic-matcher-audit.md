## 한 줄 요약

인계받은 1번(주제 매처 감사)을 끝냈다. 매처의 한국어 쪽에 **불용어 바닥이
아예 없었고**, 그 탓에 서로 다른 일곱 개의 사실이 하나로 묶여 있었다.
고쳤더니 **술어 정밀도는 45% 올랐는데 3축 지표는 전부 0.00 움직였다.**
지표가 안 움직인 것이 실패가 아니라, **골드셋 20문항이 그 오탐을 하나도
밟지 않는다는 사실의 발견**이다 — 다음 대상이 거기서 나온다.

## 이번 세션이 한 일

`78090a5` 하나다. 한국어 불용어 접두 목록(`_KO_STOPWORD_PREFIXES`) 신설 +
골드셋 긴 답변 슬라이스 4쌍 + 감사 러너 3종 + 계획서.

측정 근거는 계획서 §5에 전부 있다. 요점만:

- **술어 정밀도 45%** — 무작위 20만 쌍 수용률 19.2 → 10.6.
- **골드셋 무회귀** — 전 슬라이스 동일, `same` 재현율 불변. 정밀도만 올랐다.
- **새 게이트** — 추가한 4쌍은 구 매처에서 `GATE FAIL`, 신 매처에서 `PASS`.
- **저장 매핑** — valuein 604 → 502, 본 레포 43 → **48로 증가**.
  노이즈를 양쪽에서 빼면 분모도 줄어서 진짜 같은 주제인 쌍은 비율이
  **올라간다.** 임계값 상향과 다른 점이 이것이다.

**라이브 인덱스에도 반영해 뒀다** (`recompute_supersession.py`를 실제
config로 1회 실행). 커밋 훅을 우회했으므로 이 단계가 필요했다.

## 다음에 할 것 (우선순위)

### 1. Set A 골드셋이 매처 정밀도에 무감각하다 — **최우선**

이번 세션의 진짜 발견이다. **209건의 잘못된 supersession 대체가 사라졌는데
20문항 중 단 하나도 순위가 바뀌지 않았다.** 골드셋이 그 실패 유형을 아예
밟지 않는다는 뜻이다.

이건 인계 문서의 "Set A n=20 천장" 항목이 숫자 문제가 아니라 **커버리지
문제**라는 뜻이기도 하다. 문항을 20 → 40으로 늘려도 같은 유형만 늘면
여전히 못 본다.

**첫 걸음**: 사라진 209건 중 **실제로 답을 가로채고 있던 것**을 찾는다.
`topic_predicate_rate.py`로 구/신 매처가 갈리는 쌍을 뽑고, 그중 오래된 쪽이
어떤 질문에 답하고 있었는지 본다. 그 질문이 곧 골드셋에 없는 문항이다.
**측정 대상에서 문항을 캐는 것이지, 문항을 지어내는 게 아니다.**

주의: 후보에 실명·발화가 섞이므로 `## Answer excerpt` 본문에서만 캘 것
(P0 골드셋 확대 때 쓴 방법과 같다). 골드셋은 레포 밖에 둔다.

### 2. Reflector 클러스터링 — 매처 소비자는 셋이 아니라 넷

인계 문서가 적은 세 곳 외에 **`memory/reflector.py`가 같은 엄격 술어로
클러스터링한다.** 이번 변경으로 앞으로의 묶음이 더 좁아진다. 수동 트리거라
측정하지 않았다 — 다음 Reflector 실행 때 클러스터 크기를 기록할 것.

그리고 계획서 §6.2가 지목한 것: 수정 후에도 통합 노트 7건 중 6쌍이 묶이는데,
그건 매처가 **맞다**. 사실상 같은 반복 질문이 3개의 노트로 증류된 것이라
**Reflector 클러스터링 문제**다. 헤드 선택은 그중 하나만 노출한다.

### 3. 대화 레인 — 어휘 불일치 (벡터 작업)

인계 문서 §2 그대로 유효하다. Set B 0.02에서 안 움직인다. 41문항 중 15개는
질의와 정답이 단어를 하나도 공유하지 않는다. 처방은 문장 단위 **벡터** 색인.
1번을 먼저 하라는 이유도 그대로다 — 헤드 선택이 그 순위를 읽는지부터
확인해야 한다.

## 측정 규약 — 이번에 하나 늘었다

인계 문서의 규약(스냅샷 rsync → 3축 → 골드셋 검증)은 그대로 유효하다.
**여기에 한 줄이 추가된다:**

```bash
# 매처를 고쳤으면, 스냅샷 안의 supersession 매핑을 다시 계산해 넣어야 한다.
# 이 매핑은 인덱스 시점에 저장되므로, 안 하면 매처 변경이 측정에 보이지 않는다.
# 임베딩이 아니라 순수 CPU — 재인덱싱 비용 없음.
python benchmarks/recompute_supersession.py --config $SNAP/config.toml

# 그리고 구 매처로도 한 번 돌려 기준선이 안 움직이는지부터 확인할 것.
# (이번엔 604 → 604로 동일했다. 움직였다면 스냅샷이 이미 오염된 것이다.)
```

**매핑 개수는 정밀도의 대리 지표가 아니다.** 완전 연결 묶음이라 멤버가
재배치되면서 개수가 양방향으로 움직인다(이번에 제거 209 / 추가 107 /
대상변경 136인데 순변화는 -102였다). 대신 **술어 수용률**을 볼 것:

```bash
python benchmarks/topic_predicate_rate.py --config $SNAP/config.toml \
  --project <이름> --pairs 200000
```

## 주의사항 — 인계된 지뢰 + 이번 것

인계 문서의 7개는 전부 유효하다. 특히 #1(레인 단독 측정은 파이프라인을
예측하지 못한다)에 **성격이 다른 다섯 번째 사례**가 붙었다. 앞의 네 번은
*점수를 올리려는* 변경이 0을 냈다. 이번 것은 *파괴적 동작을 막는* 변경이고,
0이 나온 것은 **골드셋이 그 파괴를 안 밟기 때문**이다. 같은 0이지만
읽는 법이 다르다 — 전자는 되돌리고, 후자는 채택하고 골드셋을 고친다.

여기에 이번 것 둘:

8. **측정된 비용이 있고 측정된 이득이 없으면 싣지 않는다.** 불용어 목록을
   패러다임까지 완성하는 것은 구현·측정 후 되돌렸다(정밀도 10.6 → 10.1,
   Set A MRR 0.571 → 0.546). 그래서 `합니`는 있고 `했습`은 없다 — 오탈처럼
   보이지만 결정이고, 주석과 테스트에 박아 뒀다. **무심코 채우지 말 것.**
9. **2글자 접두는 기능어와 주제어를 구별하지 못한다.** 그래(그래프),
   그리(그리드), 이미(이미지), 자기(자기오염) — 불용어 목록에 넣으면
   주제어가 죽는다. 단위 테스트가 이 넷을 지킨다. 목록에 뭘 추가하든
   **코퍼스에서 접두 충돌부터 확인할 것.**
