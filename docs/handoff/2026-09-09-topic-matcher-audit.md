### 알아 둘 것 다섯 가지

**0. 문항을 더 쓰는 게 아니라 계측기를 만들어야 했다.**
"골드셋 커버리지"가 최우선이었는데, 문항을 40개로 늘려도 다음 사고는 다른
곳에 떨어진다. 문제는 문항 수가 아니라 **재는 대상**이었다 — `benchmarks/`의
모든 러너가 "답이 나왔는가"를 묻고, **"갖고 있던 답을 지웠는가"를 묻는 러너가
없었다.** 이 프로젝트를 가장 아프게 한 두 사고가 정확히 그 종류였고 둘 다
손으로 찾았다. `displacement_audit.py`가 그것을 잰다.

**1. 골드셋 88쌍은 코퍼스 거동을 못 본다 — 오늘 두 번 확인했다.**
첫 번째: 209건의 잘못된 대체가 사라졌는데 Set A 20문항이 하나도 안 움직였다.
두 번째: 형태소 백엔드가 전 슬라이스를 통과하면서 코퍼스 수용률이 10.6 → 14.5로
**올랐고**, 늘어난 쌍은 눈으로 보면 쓰레기였다.
→ 그래서 `benchmarks/topic_threshold_sweep.py`를 만들었다.
**골드셋 = 재현율 바닥, 실제 코퍼스 = 정밀도 신호.** 임계값을 만질 때 이걸 쓴다.

**2. 손목록은 연구의 대체물이 아니라 분석기의 대체물이었다.**
영어 불용어 100개 중 99개는 이미 `stopwordsiso`의 부분집합이다. 한국어는 절대
표준이 없고, 있는 목록(595개)은 이 프로젝트가 의존하는 주제어(근거·결론·기준)를
죽인다. 우리 목록의 60%는 활용형인데, 외부 목록이 활용형을 안 갖는 이유는
전부 **형태소 분석기를 앞단에 가정**하기 때문이다.

**3. 프로젝트 자기 이름이 그 코퍼스에서 만점 가중치를 받고 있었다 — 고쳤다.**
셸 프롬프트·워크트리 경로·인용된 절대경로에 다 박혀 있는데 snake_case라
식별자 3배를 받는다. 이름은 **아는 값**이므로(레지스트리, `HybridResult.project`)
추정 없이 0.3으로 내렸고, 네 소비자 전부에 흘렸다. 문제의 쌍은 변별 공유
토큰이 2 → **0개**가 됐다.

**4. `## Answer excerpt`가 없는 레코드가 질문 겹침 하나로 묶이고 있었다.**
`_QUERY_ONLY_OVERLAP`(0.6)은 질의 시점 후보용 값인데 코퍼스 전체에 그대로
적용됐다. 3번과 겹치는 부류라 함께 손봤지만 **중복은 아니다** — 정체성 데모션을
켠 채 0.85를 0.6으로 되돌리면 수용률이 9.7 → 10.5로 오른다.

## 다음에 할 것 (우선순위)

### 1. 대칭 겹침 바의 재현율 비용 — **최우선**

정밀도와 재현율을 **둘 다** 재는 도구가 생겼다.
`displacement_audit.py`(맵이 지운 것 중 몇 건이 답을 파괴했나) +
`supersession_recall.py`(바가 거절한 정정 중 몇 건이 진짜였나, 프로브 수준까지).
**한쪽만 보면 반드시 속는다** — 정밀도만 재면 아무것도 안 대체하는 게 만점이고,
재현율만 재면 전부 대체하는 게 만점이다.

지금 정밀도는 **100%(9/9)**인데 재현율은 **프로브 31%가 정정을 잃는다.**
원인은 대칭 겹침 바 하나다 — 508건 중 **467건**을 자르고 그중 **40%가 진짜
정정**이다.

**임계값으로는 못 푼다.** 0.29 아래로 내리면 damage가 되돌아온다(계획서 §6.3의
분리표). 두 갈래가 있다:
- **더 나은 특징**을 찾는다. 대칭 겹침이 지금 재는 것보다 damage를 잘 가르는 것.
- **교체를 포기한다.** 자리가 남으면 이미 삽입으로 처리한다. 정원이 찼을 때도
  교체 대신 포기하면 재현율 비용이 사라지고 정밀도는 그대로다 — 대신 낡은 답이
  남는다. **잴 수 있는 질문이고, 두 계측기가 다 있다.**

라벨이 44건(밀어냄 21 + 컷 23)뿐이라 여기서 임계값을 더 만지면 픽스처
과적합이다. 표본을 늘리거나 특징을 바꿀 것.

**둘 다 얼린 스냅샷에만 돌릴 것** — supersession 테이블을 임시로 바꿨다 복원한다.

### 2. Reflector 클러스터링

매처 소비자는 셋이 아니라 **넷**이다 — `memory/reflector.py`가 같은 엄격 술어로
클러스터링한다. 이번 변경들로 묶음이 좁아진다. 수동 트리거라 미측정이니
**다음 Reflector 실행 때 클러스터 크기를 기록할 것.**

그리고 통합 노트 7건 중 6쌍이 여전히 묶이는데, 그건 매처가 **맞다** — 사실상
같은 반복 질문이 3개 노트로 증류된 것이라 **Reflector 클러스터링 문제**다.

### 3. 대화 레인 — 어휘 불일치 (벡터 작업)

인계 문서 §2 그대로 유효. Set B 41문항 중 15개는 질의와 정답이 단어를 하나도
공유하지 않는다. 처방은 문장 단위 **벡터** 색인.

## 측정 규약 — 두 줄 늘었다

인계 문서의 규약(스냅샷 rsync → 3축)에 더해:

```bash
# 1) 매처를 고쳤으면 스냅샷 안의 supersession 매핑을 다시 계산해 넣는다.
#    인덱스 시점에 저장되므로 안 하면 변경이 측정에 보이지 않는다. 순수 CPU.
python benchmarks/recompute_supersession.py --config $SNAP/config.toml

# 2) 정밀도는 매핑 개수가 아니라 술어 수용률로 본다.
#    완전 연결 재배치 때문에 개수는 양방향으로 움직인다.
python benchmarks/topic_predicate_rate.py --config $SNAP/config.toml \
  --project <이름> --pairs 200000

# 3) 임계값을 만질 때는 두 신호를 같이 쓴다.
#    골드셋 = 재현율 바닥(하드 제약), 코퍼스 = 정밀도 목적함수.
python benchmarks/topic_threshold_sweep.py --config $SNAP/config.toml \
  --project <이름>

# 4) 전조합 감사
python benchmarks/topic_pairs_audit.py --dir <프로젝트>/.hybrid-search/qa/consolidated
```

**형태소 백엔드를 켜고 끄는 법**:

```bash
pip install kiwipiepy      # 켜기 (모델 104MB)
pip uninstall kiwipiepy    # 끄기
python -m hybrid_search.cli reindex   # 필수 — 저장된 매핑이 다른 백엔드 것이 된다
```

끄고 켠 뒤 `reindex`를 안 하면 매핑이 **무시된다**(경고 후). `status`가 한 줄로
알려준다. 두 백엔드는 임계값도 다르다(`_THRESHOLDS`).

## 주의사항

인계 문서의 지뢰 7개 + 지난 회차의 8·9 전부 유효하다. 여기에 셋:

10. **어떤 목록이든 만지기 전에 코퍼스에서 문서빈도부터 볼 것.** 초안에서 `이유`를
    형식명사로 넣었다가 DF가 0%로 떨어지는 걸 보고 뺐다 — "why를 답하는 메모리"가
    `이유`를 버리고 있었다. 의견이 아니라 계측이 잡았다.
11. **한 골드 쌍을 통과시키려고 목록을 만지지 말 것.** 픽스처 과적합이다.
    기준을 먼저 말하고(예: "이 코퍼스 DF ≥ 15%인 언어일반 과정어, 도메인 명사 제외")
    한 번에 적용한 뒤 재는 것.
12. **두 지표가 반대를 가리키면 대개 한쪽이 옳은 게 아니라 원인을 못 찾은 것이다.**
    밀어냄 지표와 Set B가 반대로 갔고, 비율만 보고 트레이드오프로 접었다.
    라벨을 붙이자 Set B가 잃던 문항이 **damage 사례**였고, 진짜 원인(비단조
    묶음)을 고치니 둘이 동시에 좋아졌다.
13. **분리자를 하나씩 고르지 말 것.** 라벨만 보면 질문 겹침이 단독으로는 제일
    좋아 보였는데(damage 5/8 차단), 대칭 겹침이 재는 것과 **같은 실패를 더
    나쁜 각도에서** 재고 있었다. 넣은 뒤에 나머지가 여전히 값을 하는지 다시 볼 것
    — 안 그러면 아무것도 안 바꾸면서 재현율만 깎는 규칙이 남는다.
14. **술어를 좁혔는데 매핑이 늘면 알고리즘을 의심할 것.** greedy 완전연결
    그룹에서 짝을 읽으면 그렇게 된다. 지금은 쌍 단위라 단조롭고, 테스트가
    그 성질을 지킨다.
15. **어휘를 저정보로 내리면 그 어휘로 묻는 사람이 답을 잃는다.** 머지/푸시/배포/
    커밋/브랜치를 0.3으로 내리면 수용률은 8.5 → 5.9로 좋아지는데 Set A top3가
    0.65로 떨어진다. 무너지는 건 정확히 "메인에 올리기 전에 뭘 확인하기로 했었지"다.
    `TestDevWorkflowVocabularyStaysDistinctive`가 막고 있다.
