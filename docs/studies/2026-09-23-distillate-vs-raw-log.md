# 2026-09-23 — 증류물이 날것 로그에 밀린다 (착수 전 기준 등록)

**상태**: 사전 등록. 코드는 아직 건드리지 않았다.
**측정 기준점**: `~/.hybrid-search/benchmarks/cycle/2026-09-23.json` (코드 `4e4759c`,
스냅샷 2026-09-22 21:02). 비교는 **같은 스냅샷**에서만 한다 — 새로 얼리면 코퍼스
증가가 다시 섞인다.

## 1. 관측

주기 측정이 기억축에서만 회귀했다. 코드축은 올랐다.

| 지표 | 2026-09-12 | 2026-09-23 |
|---|---|---|
| Set A answer_found | 0.90 | 0.65 |
| Set A answer_in_top3 | 0.70 | **0.20** |
| Set A mrr | 0.6002 | **0.1648** |
| Set B answer_found | 0.1463 | 0.122 |
| Set B answer_in_top3 | 0.0488 | 0.0244 |
| 코드축 primary_top5 | 0.88 | 0.92 |
| 코드축 recall@10 · memory@3 | 0.77 · 0.16 | 0.77 · 0.16 |
| 밀어냄 damage | — | 0 (라벨 없음 18건) |

Set A 20문항 중 **답 소실 5 · 강등 10 · 동일 5 · 개선 0**. 개선이 하나도 없는
균일 하락은 잡음이 아니라 상위 슬롯의 주인이 바뀐 모양이다.

`repeat 3`의 spread가 두 세트 모두 **0.0**이다 — 얼린 스냅샷에서 이 지표들은
결정적이다. 그래서 **0.05 이상 움직이면 실재**로 읽는다.

## 2. 무엇이 밀어냈나 (단일 사례 해부)

소실로 판정된 한 문항(`C4`, 배포 단계 순서를 묻는 회상 질문)을 스냅샷에서 직접
조회했다.

- 답을 담은 레코드는 **지워지지 않았다.** `qa/consolidated/` 아래, reflector가
  증류해 만든 통합 레코드다.
- 그 레코드의 순위: 2026-09-12에 **2위** → 지금 **12위**. 벤치가 보는 10위 창
  바로 밖이다.
- 1~11위의 구성: 대화 청크 2, 원본 일일 qa 6, 커밋 청크 2. **증류물은 12·16위**.
  1~11위의 원본 qa 중 여럿은 9/12 이후에 생긴 것이다.

## 3. 원인 후보와 배제

| 후보 | 판정 |
|---|---|
| 검색·융합 코드 변경 | **배제.** 9/12 이후 `search/`·`index/` 변경은 워크트리 정규화 3곳뿐이고, 벤치는 워크트리가 아닌 본 체크아웃을 cwd로 넘긴다 — 분기가 같다. |
| 임베딩 백엔드 강등 | **배제.** 9/22의 중단된 실행(벡터 레인이 의심되던 시점)과 9/23 정상 실행의 Set A가 소수점 넷째 자리까지 같다(0.65 / 0.20 / 0.1648). |
| supersession이 답을 보관소로 옮김 | **배제.** 해당 레코드는 `qa/consolidated/`에 그대로 있다. |
| 코퍼스 증가에 의한 희석 | **유력.** 측정 사이에 대상 프로젝트 qa가 729건 늘었다(전체 2,013건의 36%). |

여기서 남는 질문이 이 조사의 주제다: 희석 자체는 막을 수 없다. 막을 수 있는 것은
**답을 담은 증류물이 그 증류의 재료가 된 날것 로그에게 밀리는 것**이다.

## 4. 가설

reflector가 만든 통합 레코드는 자기 재료(원본 일일 qa)와 어휘가 겹치므로, 코퍼스가
자랄수록 **재료 여러 건이 각각 증류물보다 위에 서고** 상위 K를 함께 채운다.
증류물 한 건이 이기는 게 아니라 재료 n건에 자리를 빼앗긴다.

## 5. 사전 등록 — 판정 기준

착수 후 결과를 보고 기준을 정하면 자기 계측기로 자기를 통과시킨다. 그래서 **지금**
적는다. 모두 같은 스냅샷, `repeat 3`, 같은 골드셋에서 잰다.

**성공 게이트 (둘 다 넘어야 채택)**
- `Set A answer_in_top3 ≥ 0.50` (현재 0.20)
- `Set A mrr ≥ 0.40` (현재 0.1648)

**방향 지표 (게이트 아님, 보고만)**
- `Set A answer_found ≥ 0.80` (현재 0.65)
- `Set B answer_in_top3 ≥ 0.0488` (9/12 수준 복귀)

**회귀 금지 — 무변동 항목까지 미리 적는다**
- `코드축 primary_top5 ≥ 0.90` (현재 0.92, 0.02는 잡음으로 본다)
- `코드축 recall@10 ≥ 0.77` · `memory@3 ≥ 0.16` (현재값 이상, 하락 불가)
- `밀어냄 damage = 0` (라벨된 damage가 새로 생기면 실패)
- `mean_memory_hits` 9.9 ± 0.5 — 기억 레코드를 결과 목록에 더 밀어 넣어서
  이기는 것은 성공이 아니다. 코드 레인의 자리를 빼앗은 것이다.
- 한국어 회상 쿼리 한 건의 `hybrid_search` 지연 p50 ≤ 1.2s (현재 로컬 0.5~0.8s)

**기각·중단 조건**
- 위 회귀 금지 항목을 지키면서 `answer_in_top3`를 0.35 위로 올릴 수 없으면 가설이
  틀린 것이다. 문제는 레코드 종류가 아니라 회수 깊이·융합이므로, 그 가설로 다시
  열고 이 문서에 기각을 적는다.
- `limit`·깊이를 키워서 게이트를 통과하면 그것은 "창을 넓힌 것"이지 순위를 고친 게
  아니다. 그 경우 **읽기 비용**(`context_pack_bytes_mean`, 현재 코드축 11,967B)의
  증가를 함께 적고, 순위 수정과 구분해 기록한다.

## 6. 계측기 갭 (따로 고칠 것)

밀어냄 감사는 오늘 `damage 0`을 냈다. 그런데 실제로 벌어진 일은 "지워짐"이 아니라
**"10위 창 밖으로 밀림"**이다. 감사가 그 사건을 세지 않는다.

- 처방: 감사에 순위창 이탈(이전 주기에 top-K였다가 이번 주기에 K 밖) 카운터를
  추가한다. damage를 대체하지 않고 **나란히** 보고한다 — 실험 도중에 기존 자를
  바꾸면 이번 비교가 무효가 된다.
- 오늘의 기준값은 Set A 기준 **소실 5 · 강등 10 · 개선 0**이다.

## 7. 이 문서가 재지 않는 것

- 코퍼스 증가 자체를 늦추는 것(qa 적재량 제한)은 여기서 다루지 않는다. 기억이
  쌓이는 것은 이 도구의 목적이다.
- 판정 대기 밀어냄 18건은 사람 라벨이 필요하다(`judge_displacements.py`).
  사람 라벨은 절대 덮어쓰지 않는다.
- 코퍼스 내용은 인용하지 않는다. 문항은 ID와 요약으로만 적는다.
