# 하이브리드 융합 — 문헌이 권한 것을 셋 다 재봤다

**조사** 2026-09-11 · **계기** 회상 질의에서 정답이 메모리 레인 BM25 1위인데
결과에 안 나오는 사례(Set A C18·C7·C20) · **전말** `docs/handoff/2026-09-11-note-identity.md` §10~13

---

## 0. 우리가 쓰는 것

메모리 레인은 BM25 상위와 벡터 상위를 **가중 RRF**로 섞는다.

```
score = w/(k + bm25_rank) + (1-w)/(k + vector_rank)      k = 60
w = QUERY_WEIGHTS[query_type]                            한국어 자연어 = 0.15
```

## 1. 우리가 발견한 결함 — 가중치가 기울기가 아니라 벽이다

레인은 BM25에서 **429개**, 벡터에서 정확히 **memory_depth(50)** 를 가져온다.
RRF는 레인에 든 문서에 **바닥값을 항상 준다**(꼴찌여도 0이 아니다).

```
벡터 순위가 없는 문서의 최대 점수 = 0.15/(60+1)  = 0.0025
벡터 순위가 있는 문서의 최소 점수 = 0.85/(60+50) = 0.0077
```

**429개 중 어휘 1위라도 벡터 50위를 이길 수 없다.** 부등식으로 풀면
`w > 61/171 ≈ 0.357`이어야 지배가 사라진다.

부수적으로: 상위 20개를 `rrf_score × (1 + 0.6·coverage)`로 재정렬하는 어휘 리랭커가
**이 경우를 원리적으로 구제하지 못한다** — 이미 실격된 점수에 1.6을 곱해도 실격이다.
어휘 증거를 버린 뒤에 어휘로 재정렬하는 구조다.

## 2. 문헌

| 출처 | 주장 | 우리와의 관계 |
|---|---|---|
| [Bruch et al., *An Analysis of Fusion Functions for Hybrid Retrieval*](https://dl.acm.org/doi/10.1145/3596512) (TOIS 2023) | 정규화 점수의 **볼록 결합(CC) > RRF**. RRF는 파라미터에 민감하고 성능이 **비평활**하다. CC는 파라미터 하나로 표본 효율적으로 튜닝된다 | §1의 벽이 그 비평활성의 실례다 |
| [vstash](https://arxiv.org/abs/2604.15484) (2026) | RRF에 **질의별 적응 IDF 가중치**. BEIR 5종 전부 NDCG@10 개선(ArguAna +21.4%). 질의의 **74.5%에서 두 레인 top-10이 불일치** | 고정 가중치 하나가 틀린 도구라는 뜻 |
| [MEMTIER](https://arxiv.org/abs/2605.03675) (2026) | 다섯 신호 가중 검색 + **PPO로 가중치 학습**. LongMemEval-S 0.382 | 우리 규모에 과함 |
| [SGMem](https://arxiv.org/html/2509.21212v1) | 문장으로 찾아 부모 반환 → LongMemEval top-5 **+1.4pt** | 이 축의 이득 크기 기준점 |

## 3. 처방 A — 전역 가중치를 옮긴다. 기각

근거는 있었다: `KOREAN_NL = 0.15`의 이유는 "한국어 질의는 **영어 식별자로 된 코드**와
어휘가 안 맞으니 벡터에 기대라"인데, 메모리 레인의 레코드는 **질의와 같은 사람이 쓴
한국어 산문**이다. 레인이 코드용 상수를 물려받았다.

| | Set A found | Set A **top3** |
|---|---|---|
| 기준선 (w=0.15) | 0.75 | **0.70** |
| w=0.5 | 0.80 | **0.60** |
| w=0.5 + 레인 깊이 대칭 | 0.80 | **0.55** |

**논증은 우아했고 실측에서 졌다.** 어휘 영향력을 올리면 정답을 더 데려오지만
(found↑) 더 좋은 답을 밀어낸다(top3↓). 0.15는 top3 기준에서 실제로 맞게 잡혀 있었다.

## 4. 처방 B — 융합 함수를 CC로 바꾼다. 기각

CC는 §1의 벽을 **새 상수 없이** 없앤다. RRF의 바닥값이 사라지기 때문이다.

| | 가중 RRF | 정규화 CC |
|---|---|---|
| BM25 1위 · 벡터 없음 | 0.0025 | **0.15** |
| BM25 없음 · 벡터 50위 | 0.0077 | **~0.00** |
| BM25 없음 · 벡터 1위 | 0.0139 | 0.85 |

메모리 레인에서 Set A 20문항 정답의 순위를 두 정규화로 시뮬레이션:

| | min-max | z-score |
|---|---|---|
| 꼬리 개선 | C18 51→26 · C20 52→36 · C7 52→45 · C11 63→51 | C18 51→**21** · C7 52→35 · C20 52→41 |
| **헤드 악화** | C2 1→3 · C3 5→10 · C6 3→6 · C13 1→2 · C14 1→5 · C15 2→5 · C17 3→9 · C19 2→8 | C3 5→10 · C6 3→6 · C13 1→2 · C14 1→4 · C15 2→5 · C17 3→9 · C19 2→8 |

**두 정규화가 같은 그림** → 정규화 선택이 아니라 코퍼스의 성질이다.
CC는 깊은 꼬리에서 낫고 헤드에서 확실히 나쁘다. 그리고 꼬리는 우리 슬롯이 더 잘
처리한다 — 슬롯은 BM25 1위를 **7위**에, CC는 21~41위에 놓는다.

> 기각 근거는 **레인 단독 시뮬레이션**이다. 이 라인의 주의사항 #1대로 그건
> end-to-end를 예측하지 못한다. 헤드 악화가 두 정규화 모두에서 8·6문항이라
> 빌드를 쓸 이유가 없다고 판단한 것이지, end-to-end로 반증한 것은 아니다.

## 5. 처방 C — 질의별 적응 가중치. 신호가 없어서 기각

vstash의 처방이다. **질의 시점에 관측 가능한 신호가 "이 질의는 어떤 레인이 옳은가"를
예측하는지** 먼저 쟀다. Set A 20문항을 정답이 더 앞선 레인으로 라벨(LEX 8 / VEC 9 /
동률 3), 후보 신호 넷의 판별력을 AUC로:

| 신호 | AUC |
|---|---|
| BM25 레인 clarity `(s₁ − mean)/std` | 0.56 |
| 벡터 레인 clarity | 0.39 |
| 질의 평균 IDF (vstash의 신호) | 0.53 |
| 질의 최대 IDF | 0.41 |
| **clarity 차이 (bm − vec)** | **0.64** |

**전부 동전던지기(0.50) 근처다.** 최고가 0.64인데 n=8/9에서 표준오차가 ~0.14라
1σ 안이다. 중앙값도 겹친다 — LEX meanIDF 3.39 vs VEC 3.16, maxIDF는 양쪽 5.52.

**왜 vstash와 다른가**: 그쪽 이득은 BEIR 웹·QA 코퍼스에서 나온다. 질의 특이성이 넓게
분포하는 코퍼스다. 여기는 **한 사람이 같은 문체로 쓴 한국어 회상 질문 20개**라
질의 간 분산 자체가 없다. 신호가 없는 게 아니라 **이 코퍼스에서 그 신호가 상수에 가깝다.**

> **한계**: 라벨된 질의가 17개다. "이 표본 크기에서 검출되지 않는다"이지
> "존재하지 않는다"가 아니다. 가리려면 라벨된 질의를 늘려야 한다.

## 6. 그래서 우리가 한 것 — 융합을 고치지 않고 슬롯으로 우회했다

세 처방이 다 기각되고 남은 관찰은 하나였다.
**어휘 증거를 헤드 안에 넣으면 반드시 더 좋은 답 하나를 밀어낸다** — 헤드는 3칸이고
한계 문항이 정확히 3번 자리에 있다(헤드 크기는 2026-09-08에 스윕돼 3이 바닥).

그래서 헤드가 아니라 **그 아래**에 어휘 레인 자리 두 칸을 줬다. 회상 질의가 거의
안 쓰는 코드 꼬리에서 가져온다. 위에 있는 것은 아무것도 안 움직이므로 **더하기만** 된다.

| | 기준선 | 채택 후 |
|---|---|---|
| Set A found / top3 / MRR | 0.75 / 0.70 / 0.565 | **0.90** / 0.70 / **0.600** |
| Set B found / top3 | 0.12 / 0.05 | **0.15** / 0.05 |
| 코드축 top5 / recall@10 / memory@3 | 0.88 / 0.77 / 0.16 | 무변동 |

**정확히 말하면 이건 수리가 아니라 우회다.** §1의 벽은 그대로 있고, 그 위를 넘지 않고
옆으로 돌아갔다. 벽 자체를 없애려면 처방 B나 C가 필요한데 둘 다 이 코퍼스에서 졌다.

## 7. 다음 사람에게

- **처방 A·B·C를 다시 만들지 말 것.** 각각 기각 이유가 다르다 — A는 실측 교환, B는
  헤드 악화, C는 신호 부재.
- **C만 되살아날 수 있다.** 라벨된 질의를 30~50개로 늘려 AUC를 다시 재라. 0.64가
  유지되면 그건 신호다. 0.5로 수렴하면 이 코퍼스에는 없는 것이다.
- **새 융합 아이디어는 레인 단독으로 먼저 시뮬레이션하라.** 오늘 CC를 그렇게 걸러
  25분짜리 재임베딩·빌드를 안 썼다. 단 그 판정은 예측이 아니라 **필터**다.
