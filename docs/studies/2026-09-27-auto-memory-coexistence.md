# Claude Code auto memory 와의 공존 — 이중 주입 실측 (2026-09-27)

**질문** (계획 `2026-09-27-open-the-doors.md` §3 0-3): 우리 SessionStart · UserPromptSubmit 주입과
Claude Code auto memory 가 같은 내용을 두 번 넣는가? 넣는다면 얼마나?

## 1. 두 채널이 실제로 넣는 것 (이 레포 트랜스크립트 14개에서 확인)

| 채널 | 언제 | 무엇 |
|---|---|---|
| auto memory | 세션 시작, 시스템 프롬프트 | `MEMORY.md` 인덱스(첫 200줄/25KB). 토픽 파일은 모델이 필요할 때 **Read** 로 연다 — 자동 첨부 레코드는 트랜스크립트에 없다 |
| 우리 SessionStart | 세션 시작 | 최근 Q&A 요약 몇 줄 · selfeval 한 줄 · (주기 측정 안내) |
| 우리 UserPromptSubmit | 탐색형 프롬프트마다 | pre-fetch 상위 히트(≤6, ≤2,400자) — 코드 위치 · 인용된 qa/대화/커밋 |

2026-08-31 플랫폼 조사(공식 문서 확인)의 사실: auto memory 에는 과거 대화 검색이 없고, 트랜스크립트는
`cleanupPeriodDays` 뒤 지워진다(메모리 디렉터리만 남는다).

## 2. 사전 등록 (측정 전)

- **대상**: 이 레포의 Claude 트랜스크립트 전부. 우리 주입은 `hook_additional_context` 첨부에서 읽는다.
- **auto memory 코퍼스**: `MEMORY.md` + 토픽 파일. 턴마다 **그 턴 시각 이전에 만들어진 파일만** 쓴다
  (파일 생성 시각 기준 — 나중에 쓴 메모리를 과거 주입과 겹친다고 세지 않기 위해). 내용은 현재 판본이다(한계).
- **겹침 판정**: pre-fetch 히트 하나(또는 SessionStart 주입 하나)가 그 턴에 유효한 메모리 파일 하나와
  고유 id 1개 이상 또는 3어절 문구 2개 이상을 공유 — selfeval v1.2 인용 채택과 같은 규칙
  (`selfeval_evidence.quoted_adopted`), 배제 텍스트는 사용자 프롬프트.
- **보고**: (1) 크기 — 세션당 MEMORY.md 글자 수, SessionStart 주입 글자 수 중앙값, 턴당 pre-fetch 글자 수 중앙값.
  (2) 겹침 — pre-fetch 주입 중 겹치는 히트가 1개 이상인 비율, 히트 단위 비율, 히트 종류별(코드 · qa · 대화 · 커밋).
  (3) SessionStart 겹침 비율. (4) 겹침이 많은 메모리 파일 상위 5(파일명만). (5) 정밀도 표본 — 겹침으로
  판정된 히트 최대 10건을 판정자가 읽고 "같은 사실을 두 번 넣었나"를 예/아니오.
- **예측**: 겹침은 0 보다 크다. pre-fetch 히트의 **다수는 겹치지 않는다**(메모리는 큐레이션된 결론이고
  pre-fetch 는 코드 위치와 원시 턴이다). 겹침은 qa · 대화 히트에 몰리고 코드 히트에는 거의 없다.
- **판정 기준**: 히트 단위 겹침이 20% 이상이거나 겹침의 정밀도가 과반이면서 비율이 10% 이상이면 "충돌이
  실재" 로 보고 해법을 **제안만** 한다(주인 판단). 그 밖이면 README 에 공존 방식만 적는다.
- 측정 중 src 수정 없음. 출력은 레포 밖. 메모리 본문·주입 원문은 이 문서에 인용하지 않는다.
