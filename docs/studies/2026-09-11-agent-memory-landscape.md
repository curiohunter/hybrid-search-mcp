# 에이전트 메모리 지형 — 남들은 무엇을 재고, 무엇을 안 재나

**조사** 2026-09-11 · **계기** 통합 노트가 원본 기록을 지우는 결함을 고치면서,
이게 이미 알려진 문제인지 확인 · **관련** `docs/handoff/2026-09-11-note-identity.md`

## 1. supersession / 낡은 기억

| 출처 | 무엇을 하나 |
|---|---|
| [Supersede](https://arxiv.org/abs/2606.27472) (2026) | 메모리 **업데이트 격차**를 진단하고 그걸 학습 신호로 만든다. 작은 모델을 그 환경에 파인튜닝해 holdout supersession 정확도를 거의 두 배로 |
| [STALE](https://arxiv.org/abs/2605.06527) (2026) | 세 축으로 나눈다 — 낡은 믿음 **탐지**, 낡은 전제를 깐 질문 **거부**, 바뀐 정보의 **행동 반영**. 최고 모델이 55.2% |
| MemConflict (arXiv 2605.20926) | static conflict — "나중의 잘못된 모순이 안정된 사실을 덮어쓰면 안 된다" |
| [Don't Ask the LLM to Track Freshness / 결정론적 레시피](https://arxiv.org/abs/2606.01435) (2026) | 검색이 근거를 찾아도 **의미 필터링·충돌 해소·선행 억제·생성을 한 단계에 엮으면** 실패한다. 증거 추출과 정책 실행을 **분리**하라 |

**공통점**: 전부 **"최신 사실을 썼는가"** 를 잰다.

**우리가 재는 것은 그 반대편이다** — "억제가 아직 유효한 기억을 **지웠는가**".
`benchmarks/displacement_audit.py`가 맵 ON/OFF로 결과 집합을 비교해 그것만 본다.
찾은 문헌 중 이 축을 지표로 삼는 곳은 없었다.

> **과장하지 말 것.** 외부 심사(DeepSeek)가 지적했듯 이건 MemConflict의 static
> conflict와 **개념적으로 같은 실패**를 다른 각도에서 재는 것이다. 새 *문제*가 아니라
> 새 *계측기*다. 그리고 그 계측기는 우리가 만들었고 라벨러도 한 명이다.

## 2. consolidation — 요약이 원본을 대체하면

| 출처 | 요지 |
|---|---|
| [Manufactured Confidence](https://arxiv.org/abs/2606.29279) (2026) | 통합이 **전언을 확신에 찬 사실로** 바꾼다 |
| [RecMem](https://arxiv.org/abs/2605.16045) (2026) | 재귀 기반 통합 |
| [LongMemEval-V2](https://arxiv.org/abs/2605.12493) (2026) | "경험 있는 동료"를 향한 장기 메모리 평가 |
| 업계 정리 | 통합은 **선택적**일 때 효과적이다 — 미해결로 두지도, 너무 공격적으로 압축하지도 않을 때. **원문은 정확한 표현을 더 잘 보존한다** |

마지막 항목이 우리 2026-09-11 결함과 정확히 같은 말이다. 노트는 그 세션의 결론을
종합하면서 그 세션이 열거한 목록 하나를 버렸고, 프로브가 찾던 게 그 목록이었다.
**그래서 우리 처방(노트는 자기 답을 가진 원본의 슬롯을 못 빼앗는다)은 문헌과 같은
방향이다** — 통합 노트는 `supersedes`가 아니라 `derived_from` 관계라는 것.

## 3. 벤치마크 — 왜 우리 숫자를 남의 자로 못 재나

[LongMemEval](https://github.com/xiaowu0162/longmemeval) (ICLR 2025)의 스키마:

```
{question_id, question_type, question, answer, question_date,
 haystack_session_ids[], haystack_dates[], haystack_sessions[][{role, content}],
 answer_session_ids[]}                       # 턴 단위로는 has_answer: true
```

어댑터는 쉽다 — user→assistant 한 쌍을 qa 레코드 하나로 옮기면 된다.
**막히는 것은 코퍼스 구조다**: LongMemEval은 **문항마다 자기 haystack**(세션 ~50개)을
갖고 우리는 **프로젝트당 인덱스 하나**다. 선택지 둘 다 비교 가능성을 깬다 —
문항당 프로젝트를 만들면 knowledge-update 서브셋만 해도 **8시간**(로컬 ollama
실측 1.2 레코드/초), 전부 합치면 원 벤치보다 어려운 과제라 논문 수치와 비교 불가.

**결론**: 선행 결정("일반 메모리 벤치 점수 경쟁을 하지 않는다")이 옳았다는 근거가
하나 늘었다 — 점수가 아니라 **인덱스 단위**가 안 맞아서다.

## 4. 우리 위치 (정직하게)

**앞서 있는 것**: 억제가 유효 기억을 지웠는지를 재는 축. 다만 계측기·라벨 전부
자체 제작이고 n=1 라벨러다.

**같이 가는 것**: 통합 노트와 원시 턴의 동거, `derived_from`과 `supersedes`의 구분,
증거 추출과 정책 실행의 분리.

**뒤처진 것**: 비교 가능한 공개 숫자가 없다. 위 §3 때문에 당분간 없을 것이다.
그리고 융합은 문헌 처방(적응·학습 가중치)보다 한 단계 아래다
([하이브리드 융합](2026-09-11-hybrid-fusion.md) 참조 — 재보고 기각했지만 우회는 우회다).
