(2026-07-26에 확립한 관례) · **보낸 것** 지표·구조·chunk id만. 코퍼스 발화는 보내지 않았다.

**심사 대상**: 통합 노트가 원본의 슬롯을 빼앗아 답을 지우는 결함의 처방 셋.

## 심사가 지목한 미관측 실패 모드 (원문 요지)

- **의도 불일치** — "최신" 질의와 "당시" 질의를 구분하지 않는다. 맵은 항상 옛 답을 숨긴다
- **연쇄 오염** — 잘못된 엣지 하나가 A→B→C로 번진다. 전이 폐쇄 감사가 필요하다
- **top-k와 집합 비교의 불일치** — 결과 집합에 남아도 top3 밖으로 밀리면 사용자 지표는 망가진다
- **후계자 품질** — 최신이 더 나쁘거나 hallucination이어도 splice는 최신을 우선한다
- **가드 게이밍** — 후계자가 질의어만 언급하고 답을 안 담아도 "잃은 어휘"가 없어 통과한다
- **표본 크기** — 4/6, 7/10, 8/120은 신뢰구간이 넓고 서로 겹친다

> 이 중 **연쇄 오염**과 **의도 불일치**는 아직 계측기가 없다. 다음 라운드 후보다.

## 심사가 지정한 "순환을 깨는 측정"

1. 특징 선택용 코퍼스와 평가용 코퍼스를 분리하고, **3차 코퍼스를 동결**해 사전 등록 후 처음 연다
2. "결과 집합에서 사라졌는가"가 아니라 **ON top-k만 보고 독립 reader가 정답을 맞히는가**로 평가
3. 각 밀어냄에 **원본만 답하는 프로브**와 **후계자만 답하는 프로브**를 만든다
4. 원본 답변에서 **atomic subquestion**을 생성해 ON 결과가 그것을 답하는지 기계적으로 검사
5. ON/OFF를 숨기고 순서를 무작위화한 **블라인드 라벨링** + LLM 제2 판정, 불일치율 보고

**이 세션에서 한 것**: 1의 절반(2차 코퍼스를 라벨해 두 코퍼스로 재는 체계),
그리고 사전 등록. **2~5는 안 했다.**

## 부록 — 심사가 권한 것을 재보고 접은 항목

**"저정보 어휘 배제 / 고유 엔티티 요구"**로 구조 A damage를 막으라는 권고를
코퍼스 문서빈도로 검증했다(주의사항 #10: 목록을 만지기 전에 DF부터).
1차 코퍼스 질문 1,915건 기준, 라벨된 엣지의 공유 질문 토큰 DF:

| 판정 | 공유 토큰 (DF%) |
|---|---|
| damage | 4.1 / 3.8 |
| damage | 5.7 / 3.7 |
| damage | 4.2 / 1.1 / 0.8 |
| legitimate | 3.7 / 3.2 / 3.1 |
| legitimate | 5.1 / 4.8 |
| legitimate | 2.3 / 2.0 |

**두 부류가 같은 구간에 있다.** "DF 2% 미만 토큰 최소 하나" 규칙이면 damage 3건 중
2건을 막고 **legitimate 6건을 잃는다.** 공유 토큰 **개수**도 안 가린다(damage 2·2·3,
legitimate도 2·2·2·3·3).

**그래서 이 라인이 임계값에서 네 번 진 이유가 특징 공간에 있다.** 남은 damage는
어휘 밖의 신호 — 명시적 정정 큐, 같은 세션/턴 여부, 엣지 타입 — 로만 갈린다.
