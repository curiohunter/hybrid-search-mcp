## 3. 0단계 — 문 열기 전 점검

### 0-1. selfeval 계측 수정 (최우선)
지금 계측기로는 런칭해도 "도움이 되는지"를 잴 수 없다.
- 결함 A: `_SHELL_SEARCH_PREFIXES` 로 시작하는 Bash 는 대상이 **결과에 있던 파일이어도**
  검색(배신)으로 센다. 에이전트는 `grep -n`/`sed -n` 을 파일 읽기에 쓴다 (2026-09-23 진단:
  배신 10건 중 9건이 결과 밖 파일을 열지 않았다).
  → 명령이 결과 경로를 명시적으로 대상으로 하면 **읽기**로 분류. 결과 밖 경로 또는 경로
  없는 전역 검색만 배신.
- 결함 B: 인용 메모리 히트("quoted — no file to open")는 Read 로 채택될 수 없어 채택률이
  구조적으로 파일 히트만 잰다.
  → 인용 히트는 **최종 답변이 그 히트의 고유 문구·id 를 담았는지**로 채택을 따로 센다
  (정의는 구현 전 문서에 확정).
- 산출: 기존 이벤트를 새 규칙으로 **소급 재채점**해 분포 변화를 보고. 합성 트랜스크립트
  테스트. 채택 기준(몇 % 이상이면 좋다)은 두지 않는다 — 계측기 교정이 목적.

### 0-2. 대화 레인의 같은 결함 점검
`_merge_conv_results` 끝의 `[*live, *body[:cut], *indexed, *body[cut:]]` 가 PR #23 에서 고친
기억 head 재배치와 같은 모양인지 확인. 이미 cut 위에 있던 대화 항목을 아래로 옮기는지 사본에서
읽기만으로 센다. 같은 결함이면 PR #23 과 같은 절차(사전 등록 → 순서 보정 → 질문 판정 →
Set A/B · 코드축)로 수정. 아니면 이유를 적고 닫는다.

### 0-3. Claude Code 자동 메모리와의 공존
7월부터 미해결. 우리 SessionStart·UserPromptSubmit 주입과 Claude Code auto memory
(MEMORY.md 적재, Auto Dream)가 같은 내용을 이중 주입하는지 이 레포에서 실측하고, README 에
공존 방식을 적는다. 충돌이 실재하면 해법을 제안만 하고 주인 판단을 받는다.

### 0-4. valuein 실사용 검증 준비
과거 기록을 잘 찾는지는 valuein 실사용으로 검증한다 (주인 결정 2026-09-27).
- valuein 세션 재시작 안내(떠 있는 MCP 서버는 옛 코드를 들고 있다) — 그쪽 세션에 요청으로.
- **놓친 순간 기록 경로**: 사용자가 "전에 얘기했는데 못 찾네" 라고 하면 남길 곳. 최소
  구현: CLI `hybrid-search-mcp miss "<무엇을 찾았나>"` 가 `~/.hybrid-search/benchmarks/
  misses-<project>.jsonl` (레포 밖)에 {시각, 프로젝트, 질문, 최근 검색 질의} 를 추가. 새 MCP
  도구는 만들지 않는다. 모인 사례는 질문 판정 러너의 회귀 문항이 된다.
- 주기 측정(`benchmarks/cycle.py`)에 질문 판정을 넣을지는 0-1 결과를 보고 정한다.

불가였다 — 같은 벽이면 접는다. 진행 시 정확도 · 답변당 토큰 · 지연을 함께 보고하고 agentic
