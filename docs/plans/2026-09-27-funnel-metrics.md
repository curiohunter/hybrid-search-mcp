# 퍼널 지표 — 설계만 (2026-09-27)

**상태**: 설계. 구현하지 않았다. 상위 계획 `2026-09-27-open-the-doors.md` §5.
**원칙**: 동의한 사용자만, 자기 기계에서 만든 보고를 **사용자가 직접 붙여 넣는다**. 자동 전송 · 텔레메트리 없음
(README "No telemetry" 약속을 깨지 않는다).

## 1. 단계

| 단계 | 정의 | 로컬에서 판정하는 근거 (이미 있는 기록) |
|---|---|---|
| 설치 | 패키지가 설치됐다 | 보고를 만들 수 있다는 사실 자체 |
| 첫 인덱싱 | 프로젝트 인덱스가 1개 이상 | `~/.hybrid-search/projects/*/store.db` 존재, `files` 행 수 > 0 |
| 첫 검색 | 도구 호출 또는 pre-fetch 가 1번 이상 | `.hybrid-search/selfeval/events.jsonl` 행, 또는 `trigger: user_prompt_submit` qa 로그 |
| 두 번째 세션 재검색 | 서로 다른 세션 두 개 이상에서 검색 | selfeval 행의 `turn_key`/qa 로그 `session` 이 2종 이상 |
| 7일 잔존 | 첫 검색 후 7일 이상 지난 날에 검색 | 가장 이른 검색 시각과 가장 늦은 검색 시각의 차 ≥ 7일 |

추가로 보고할 것(수치만): selfeval v1.2 요약 줄(채택 · 인용 채택 상한 · 배신), `miss` 기록 수.

## 2. 수집 방식 (구현 시)

1. `hybrid-search-mcp doctor --report` (가칭 · 새 MCP 도구 아님): 위 표를 **숫자와 날짜만**으로 출력한다.
   질의 원문 · 경로 · 프로젝트 이름은 넣지 않는다(프로젝트는 해시로).
2. GitHub 이슈 템플릿 "usage report": 사용자가 1 의 출력을 붙여 넣는다. 템플릿 첫 줄에 무엇이 들어가고
   무엇이 안 들어가는지 적는다.
3. 집계는 수동. 사례가 쌓이기 전에는 대시보드를 만들지 않는다.

## 3. 하지 않는 것

자동 전송 · 원격 수집 엔드포인트 · 질의 원문 수집 · 동의 없는 보고.

## 4. 열린 질문 (주인)

- 보고 명령을 0.9.x 에 넣을지, 첫 외부 사용자가 생긴 뒤에 넣을지.
- 이슈 템플릿을 공개 레포에 둘지(보고가 공개된다는 뜻), 비공개 채널(메일 · 폼)로 받을지.
