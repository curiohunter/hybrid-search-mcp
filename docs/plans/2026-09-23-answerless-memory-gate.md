# 답 없는 기억은 인덱스에 들어오지 않는다 — 3층 기억의 첫 층

**상태**: A 머지 (정본 판정·카드 생성 차단·최근 활동 레인) · B 채택 (2026-09-26, 질문
기반 판정 — 연구 문서 §24, §11 항목 7). 청커 게이트와 이주 코드는
`feature/answerless-memory-gate` 브랜치 PR 로 올린다. §5 는 측정 전에
적었고(`5116055`), 결과는 §9.
**결정 배경**: 2026-09-23 주인 결정 — Jev 도입 폐기. "기억할 만한 것만 기억"을
**쓰기 시점의 중요도 판정**으로 하지 않고, 층으로 나눈다.

| 층 | 무엇 | 근거 |
|---|---|---|
| 버리기 | **종류로 판정되는** 쓰레기만 규칙으로 인덱스에서 뺀다 (파일은 지우지 않는다) | 우리 실측 (자기오염 83%, 모듈 오염 56.8%) |
| 승격 | 증류 노트를 앞줄에 (B2, 이미 됨) | LongMemEval, Generative Agents |
| 보관 | 원시 기록은 지우지 않고 뒤에 — 증류가 틀렸을 때 돌아갈 곳 | LongMemEval: 값은 원문, 사실은 열쇠 |

중요도로 거르는 쓰기(Mem0 식)는 하지 않는다 — 중요도는 질문이 올 때 정해지고,
잘못 버린 기억은 되돌릴 수 없으며, 오늘 잰 종류 라벨 정밀도(0.70)로는 삭제 기준이
못 된다. 이 문서는 **첫 층**만 다룬다.

---

## 1. 관측 (2026-09-23, 건수만 — 원문은 옮기지 않는다)

턴마다 qa 레코드가 **둘** 쓰인다 — 질문이 도착할 때(pre-fetch / MCP 도구) 하나,
답이 끝날 때(Stop 훅) 하나. `_owns_an_answer` 의 독스트링이 이미 이렇게 적고 있다:
"두 번째만 무언가를 소유한다". 그런데 이 원칙은 **재정렬 한 곳**에서만 쓰이고,
인덱스에는 첫 번째 레코드도 그대로 들어간다.

| 코퍼스 | qa 전체 | 답 없음 | 비율 |
|---|---|---|---|
| 본 레포 | 323 | 82 (prefetch 36+9 · mcp 18+2 · stop 28) | 25% |
| valuein | ~2,000 | 399 | ~20% |

답 없는 레코드의 본문 대부분은 `## Top results` — **다른 청크의 스니펫을 옮겨
적은 것**이다. 즉 기억을 다시 기억한 것이고, 제 것은 질문 한 줄뿐이다.

## 2. 발견한 버그 — "답이 있다"를 부분 문자열로 판정한다

답 유무 판정이 `"## Answer excerpt" in content` 인데, pre-fetch 레코드가
**다른 qa 레코드를 인용**하면 그 스니펫(줄바꿈이 공백으로 납작해진) 안에 같은
문자열이 들어 있다. 결과:

- 판정 오류: 본 레포 11건, valuein 49건이 "답 있음"으로 읽힌다.
- 더 나쁜 것: `split("## Answer excerpt")[1]` 이 **인용 목록 전체**를 그 레코드의
  "답"으로 돌려준다. 이 가짜 답이 주제 매칭(supersession, 재정렬 그룹, 밀어냄 감사
  프로브, Reflector 군집, 카드 요약)에 들어간다.
- "답 없는 레코드가 답을 지운다"는 모양이 세 번 반복됐다 (09-09 주제 매처 감사,
  09-23 §10, 오늘 검색). 이 버그가 그 상류 원인 중 하나일 수 있다 — **확인은 §5에서.**

정본 신호 (두 코퍼스 전수 교차표로 확인): **줄 맨 앞의 `## Answer excerpt` 제목**.
- stop_hook 답 있는 레코드, reflector 노트, frontmatter 필드가 없는 옛 레코드를
  빠짐없이 포함한다.
- 스니펫은 쓰일 때 줄바꿈이 공백이 되므로(`qa_log._truncate`) 인용 안에서는 줄 맨
  앞 제목이 생길 수 없다.
- frontmatter `answer_excerpt_chars` 는 reflector 노트·옛 레코드에 없어서 정본이 못 된다.

## 3. 변경

### A. 정본 판정 한 곳 (`memory/qa_shape.py`)
- `owns_answer(content)`, `answer_excerpt(content)` — 줄 맨 앞 제목 기준, 답은 제목부터
  `## Top results` 제목 전까지.
- 부분 문자열로 판정하던 곳을 전부 정본으로 교체: orchestrator(신뢰 메타, 주제 항목,
  `_owns_an_answer`), supersession `_topic_item`, reflector `_answer_text`, cards
  `_extract_section`, 벤치 `supersession_recall`.

### B. 인덱스 게이트 + 기존 인덱스 이주
- `doc_chunker`: qa 로그가 답을 소유하지 않으면 청크 0개.
- `pipeline._chunk_file`: 청크 0개라도 **파일 행은 기록**한다 (해시 보존 → 매 스캔마다
  다시 읽히지 않음). 옛 청크가 있으면 지운다 — 지금은 청크가 0이 되면 옛 청크가 남는다.
- 기존 인덱스: 파일 해시가 그대로라 재청킹되지 않는다. `index_meta` 표식이 없으면
  한 번 `purge_withheld_memory` — 답 없는 qa 청크를 SQLite·BM25·벡터에서 뺀다.
  **임베딩 호출 0, 비용 0** (삭제만 한다).
- 파일은 디스크에 그대로 남는다 — selfeval·감사가 계속 읽는다. 나중에 답이 붙어
  파일이 바뀌면 보통의 델타 경로로 들어온다.

### C. 카드
- `create_card_from_qa`: 답을 소유하지 않는 qa 로는 카드를 만들지 않는다 (지금은
  요약이 남의 인용 스니펫이 된다).
- 인덱스 게이트: 요약이 메타데이터 블록인 카드(09-08 이전 생성분)는 청크 0개.
- **예고 문장만 있는 카드**("확인하겠습니다" 류)는 이번에 **하지 않는다** — 본 레포
  2건이고, 판정이 어휘 휴리스틱이라 종류 규칙이 아니다. §8 에 남긴다.

## 4. 측정 절차

- 얼린 스냅샷 `~/.hybrid-search/.cycle-snapshot` (frozen_at 2026-09-22T12:03Z)을
  **사본 두 개**로 복사한다. 원본 스냅샷과 cycle 기록은 건드리지 않는다.
  - `base`: main(`80c49d2`) 코드로 측정.
  - `gate`: 이 브랜치 코드로 사본을 이주(purge)한 뒤 측정.
- 두 측정은 같은 시간대에 돈다 — 최근 활동 레인이 라이브 qa 파일을 읽는 기존
  오염은 양쪽이 같다.
- 배터리는 cycle 과 같다: supersession 재계산 → Set A/B(repeat 3) → 코드축 →
  밀어냄 감사(두 프로젝트, 홀드아웃 2026-09-12).

## 5. 사전 등록 — 판정 기준 (측정 전)

**이 변경의 목적은 쓰레기 제거지 순위 개선이 아니다.** 그래서 채택 조건은
"구조 지표가 목표대로 + 게이트 지표 무회귀"다. 개선을 요구하지 않는 이유를 미리 적는다:
답 없는 레코드는 골드의 정답이 아니므로(Set A 정답 = 노트, Set B 정답 = 원시 대화,
코드축 정답 = 소스 파일) 순위 지표가 움직일 경로는 **밀어냄 제거** 하나뿐이고,
그것이 없어도 인덱스 20% 축소와 가짜 답 제거는 그 자체로 결함 수정이다.

**구조 지표 (반드시):**
1. gate 사본의 답 없는 qa 청크 = 0 (두 프로젝트).
2. supersession 맵에서 **후계자가 답 없는 레코드**인 매핑 = 0. base 에서 몇 건인지
   같이 보고한다 — 이 수가 "상류 원인" 가설의 크기다.
3. 정본 판정과 부분 문자열 판정이 갈리는 레코드 수를 base 기준으로 보고.

**게이트 지표 (base 대비 떨어지면 안 됨; 결정적이라 spread 0, 0.05 이상이 실재):**

| 지표 | 조건 |
|---|---|
| Set A answer_in_top3 · mrr · found | ≥ base |
| Set B answer_in_top3 · found | ≥ base |
| 코드축 primary_top5 · recall@10 | ≥ base |
| 코드축 memory@3 | ≥ base, **예외**: 떨어지면 잃은 히트가 답 없는 레코드였는지 확인. 그렇다면 회귀가 아니다 (그 레코드는 남의 스니펫을 인용한 것이지 기억이 아니다) — 이 예외는 측정 전에 적는다 |
| 밀어냄 damage | 0 유지 |

**비교 불가 항목 (미리 적는다):** 밀어냄 감사의 프로브 집합은 이 변경으로
바뀐다 — 프로브 선별이 `_topic_item` 의 답 토큰을 쓰는데, 부분 문자열 오판 레코드가
지금은 프로브로 들어간다. 그래서 probes·self_retrieval 은 **교집합 프로브**에서만
비교하고, 총수 변화는 "오판 프로브 제거"로 따로 보고한다.

**예상 무변동:** 코드축 세 지표, Set B (원시 대화 레인은 qa 레코드와 경쟁하지 않는다).
움직이면 설명이 필요하다.

**기각 조건:** 게이트 지표 하나라도 base 보다 0.05 이상 떨어지고 예외로 설명되지
않으면 B 를 되돌리고 A 만 남길지 따로 판정한다.

### 9.3 B 는 왜 떨어뜨렸나 — 쓰레기가 가림막이었다

문항별로 따라갔다 (C3 · C17 · C8 · B35, 교차 실행으로 코드 대 스냅샷 분리).

- **C3 · C17 (답 소실)**: 새 코드 + 옛 스냅샷이면 노트가 1위, 옛 코드 + 새 스냅샷이면
  사라진다 → 스냅샷 쪽이다. 단계별 추적: 노트는 두 사본 모두 풀에 있고 B2 가 머리에
  앉힌다. 그 뒤 **`_order_qa_by_recency` 가 gate 에서만 노트를 1위 → 9위로 내리고**
  모듈 교차 배치에서 10위 밖으로 밀린다. 노트와 같은 그룹에 묶인 것: base 에서는
  답 없는 레코드와 노트보다 오래된 턴뿐이었고, gate 에서는 그 빈자리를 채운 **더 새
  `task_state` 레코드**다. 연구 문서 §14 가 "안전장치가 과하게 발동한다"며 멈춘 바로
  그 결함이다 — 답 없는 레코드가 목록 자리를 차지해 우연히 가리고 있었다.
- **B35 (2위 → 8위)**: base 의 2위는 답 없는 pre-fetch 레코드였고, 정답 문구가 그
  레코드의 **질문(사용자 원문)** 안에 있었다. 문구를 가진 다음 결과는 답 있는 qa
  레코드로 두 사본 모두 8위다 — 원시 턴에만 있어야 할 사실을 질문 레코드가 대신 들고
  있었던 것이고, 원시 대화 레인이 그 문구를 10위 안에 못 올리는 Set B 의 기존 문제는
  그대로다.
- **라벨 damage 1건**: 그 쌍은 base 맵에도 있었다. 목록 구성이 바뀌어 base 에서는
  발동하지 않던 splice 가 발동했다. 같은 가림막 모양이다.
- **C8 (1위 → 3위)**: 노트 그룹과 무관한 순위 이동.

**결론:** B 는 옳은 방향이지만, B 를 켜면 쓰레기가 가리던 두 결함(최근성 안전장치
과발동, 발동하지 않던 damage 쌍)이 드러난다. B2 의 0.70 도 일부는 이 가림막 위에서 잰
숫자다. **B 는 그 결함을 먼저 고친 뒤에 다시 잰다.**

### 9.4 §6 진단 — 선주입 "배신" 의 대부분은 계측기다

최근 7일 selfeval 14건: 배신 10 · 혼합 1 · 후속 없음 3.

| 분류 | 건수 | 근거 |

- 배신 판정 10건 중 9건이 "결과 밖 파일을 열지 않았다". selfeval 은 `grep`/`sed` 로
  시작하는 Bash 를 검색으로 세는데, 에이전트는 그걸 **파일 읽기**에도 쓴다.
- 메모리 히트는 "quoted — no file to open" 이라 Read 로 채택될 수가 없다. 채택률은

  찾은 것"을 가르고, 인용 메모리 히트의 채택 신호(답변 인용)를 따로 잡을 것.

### 9.5 이번 작업에서 새로 드러난 것 (범위 밖, 기록만)

1. **커밋 인식 재검증(trust layer)은 답 없는 레코드에만 붙어 있었다.** 앵커 해시는
   `record()`(질문 도착 시)만 쓴다. valuein: 앵커 있는 레코드 290건 전부 답 없음, 답
   있는 1,599건 중 앵커 0. 게이트가 켜지면 재검증 대상이 인덱스에서 사라진다 — 원래도
   답 없는 레코드에 경고를 달고 있었다. 앵커를 답 레코드로 옮길지, 무엇을 근거로 볼지
   (pre-fetch 결과 대 실제 읽고 고친 파일)는 별도 결정.
2. **Stop 훅이 없는 MCP 전용 호스트는 게이트가 켜지면 기억이 사라진다.** 지원 호스트
   (Claude Code · Codex)는 둘 다 Stop 훅이 답 레코드를 쓴다 (README "on when hooks
   installed"). B 를 다시 켤 때 명시할 트레이드오프.
3. **본 레포 라이브 인덱스는 이미 이주됐다.** 이 브랜치 커밋의 post-commit 훅이
   editable 설치로 돌았다 (`memory_gate=1`, qa 청크 230). 삭제만이라 비용은 0.
4. 계측 중 내 실수 둘 — SQL `LIKE '%trigger: reflector%'` 로 노트를 세다가 인용 속
   문자열을 잡아 "노트 3개 삭제"로 오독했다(이 작업이 고치는 바로 그 버그). 대기 루프의
   `pgrep -f` 가 자기 명령줄에 걸려 base2 가 돌지 않았다 — acode 가 같은 시간대 대조를
   대신했다.
