# selfeval v1.2 — 계측기 교정 (결함 A · B)

**상태**: 정의 확정 + 사전 등록 (2026-09-27, 구현 전). 상위 계획 `2026-09-27-open-the-doors.md` §3 0-1.
**목적**: 채택률을 올리는 것이 아니라 **계측기가 실제로 일어난 일을 세게** 하는 것. 채택 기준(몇 % 이상이면
좋다)은 두지 않는다.

---

## 1. 결함 A — 셸로 결과 파일을 읽은 것을 배신으로 셈

**지금**: Bash 명령의 머리가 `rg`/`grep`/`ag`/`ack`/`find`/`fd` 이면 대상이 무엇이든 검색(배신)으로 센다.
`sed -n`·`cat`·`head` 로 파일을 읽은 것은 아예 세지 않는다. 에이전트는 `grep -n X file` · `sed -n 1,80p file`
을 파일 읽기로 쓴다.

**정의 (v1.2)**. Bash 명령을 `&&` `||` `;` 로 나눈 각 명령의 **파이프 첫 단**만 본다(파이프 뒤의 grep 은 다른
명령의 출력을 거르는 것이지 코드 검색이 아니다 — v1.1 과 같음). 인자는 셸 인용 규칙으로 토큰화한다.

| 명령 머리 | 위치 인자 | 분류 |
|---|---|---|
| `grep` `rg` `ag` `ack` | 첫 위치 인자는 패턴(`-e`/`-f` 가 있으면 없음), 나머지는 대상 | 대상 중 **파일로 보이는 것 → 읽기**. 파일 대상이 하나도 없거나(경로 없는 전역 검색), 디렉터리·글롭 대상이 있으면 → **검색** |
| `sed` `awk` | 첫 위치 인자는 스크립트(`-e`/`-f` 가 있으면 없음), 나머지는 대상 | 파일 대상 → 읽기 |
| `cat` `head` `tail` `nl` `less` `more` `bat` | 모두 대상 | 파일 대상 → 읽기 |
| `find` `fd` | — | 항상 검색 (v1.1 과 같음) |

- **파일로 보이는 대상**: 마지막 경로 성분에 확장자 점이 있고(`.`/`..` 제외, `.gitignore` 같은 점 파일 포함)
  `/` 로 끝나지 않으며 글롭 문자(`*?[`)가 없다. 확장자 없는 파일(`Makefile`)은 디렉터리로 오분류된다 — 알려진 한계.
- 읽기로 분류된 대상은 Read 도구와 **똑같이** 채점한다: 결과 경로와 맞으면 채택, 아니면 `outside_reads`
  (배신 · 수확 대상). 즉 **결과 경로를 대상으로 한 grep/sed 는 채택, 결과 밖 경로 또는 경로 없는 전역 검색만 배신.**
- 토큰화 실패(짝 안 맞는 따옴표 등)는 v1.1 규칙으로 되돌린다.

**부수 효과 (미리 적음)**: 결과 밖 파일을 `cat`/`sed` 로 읽은 턴은 v1.1 에선 무신호였으나 v1.2 에선 배신이 된다.
Read 도구와 대칭을 맞춘 결과이며, 분포 비교에서 이 성분을 따로 보고한다.

## 2. 결함 B — 인용 메모리 히트는 구조적으로 채택될 수 없음

**지금**: 기억 레인 히트(qa 로그 · 대화 · 메모리 카드 · 커밋)는 pre-fetch 에서 "quoted — no file to open" 으로
인용되고 "Read 하지 말라"고 지시한다. 채택은 Read 로만 세므로 이 히트는 어떻게 쓰여도 `no_followup` 이다.

**정의 (v1.2)**.

- **인용 히트**: 서빙된 결과 중 도구 레인은 `node_type ∈ {qa_log, conv_turn, memory_card, commit}`, pre-fetch 레인은
  경로가 기억 레인(`.hybrid-search/` · `.conversations/` · `.git-history/`, 단 `.hybrid-search/wiki/` 제외 — 위키는 열 수 있는
  파일 히트로 렌더된다).
- **본 발췌 X**: 에이전트가 실제로 본 텍스트. pre-fetch 는 주입된 발췌(렌더 본문, ≤320자) — v1.2 부터 pending 행에 저장.
  도구 레인은 결과의 `content`(없으면 `snippet`). 소급 채점의 pre-fetch 는 qa 로그의 인용문(주입 본문과 같은 원천, 길이만 다름).
- **답변 A**: 귀속 창 안의 어시스턴트 텍스트 전부. 도구 레인은 그 검색 호출 **이후 턴 끝까지**(다음 검색에서 끊지 않는다 —
  최종 답변은 보통 마지막 검색 뒤에 오므로), pre-fetch 는 턴 전체.
- **배제 텍스트 N**: 사용자 프롬프트, 검색 질의, 그리고 같은 창의 **다른 도구 결과**(Read · Bash 출력 등). 답에 들어간 문구가
  다른 도구에서도 왔으면 이 히트에서 왔다고 말할 수 없다 — 보수적으로 세지 않는다.
- **고유 증거** E(X) = X 에서 뽑은 것 중 N 에 없는 것:
  - **id**: 16진 해시(7~40자, 숫자·문자 섞임) · `#숫자` · ISO 날짜 · 버전 `x.y.z` · 백틱 스팬(3자 이상) ·
    `_` `.` `/` 를 품은 식별자(4자 이상, 예: snake_case, 점 경로, 파일 경로).
  - **문구**: 소문자화 · 구두점 제거 뒤 연속 3어절 조각 중 길이 12자 이상.
- **채택 (quoted adopted)**: A 가 E(X) 의 id 를 **1개 이상** 담거나 문구를 **2개 이상** 담는다.
- 행에 `quoted_served`(인용 히트 수)와 `quoted_adopted_rank`(채택된 인용 히트 중 최고 순위, 없으면 null)를 더한다.
  **`verdict` 는 파일 레인 판정으로 그대로 둔다** — 인용 채택은 따로 센다(상위 계획 문구).

**알려진 한계**: 답이 히트를 **바꿔 말해** 쓰면 놓친다(재현율 손실, 정밀도 우선). 같은 id 가 사용자 프롬프트에 있으면
세지 않는다. 소급 채점의 X 는 실제 주입 본문과 길이가 다르다.

## 3. 사전 등록 — 무엇을 재고 어떻게 보고하나

측정 중 src 수정 금지. 소급 재채점은 **읽기만**: 두 레포(본 레포 · valuein)의 `events.jsonl` 과 트랜스크립트·qa 로그를
읽고, 출력은 레포 밖 `~/.hybrid-search/benchmarks/selfeval-rescore/` 에만 쓴다. 이벤트 파일은 건드리지 않는다.

1. **재현 충실도**: 저장된 행을 트랜스크립트에서 턴을 되찾아 **v1.1 규칙으로 재도출**한 판정이 저장 판정과 몇 % 일치하는가.
   되찾지 못한 행 수도 보고. 일치율이 90% 미만이면 이후 수치는 "재도출 분포"로만 읽고 저장 분포와 직접 비교하지 않는다.
2. **분포 비교**: 레포 × 레인별 `adopted/mixed/betrayed/no_followup` — (a) 저장값 (b) v1.1 재도출 (c) v1.2.
   (b)→(c) 전이 행렬과, 변화를 만든 성분(셸 읽기 → 채택 / 셸 읽기 → 결과 밖 읽기 / 검색 유지)을 따로 센다.
3. **인용 채택**: 레포 × 레인별 인용 히트를 받은 행 수, 그중 인용 채택 행 수.
4. **정밀도 표본 (로컬 판정)**: 인용 채택 행 최대 10건 + 인용 미채택 행 최대 10건을 판정자가 읽고 "답이 이 히트를 썼나"를
   예/아니오로 적는다. 결과는 레포 밖에만 저장, 수치만 보고.

**예측 (방향만, 크기 미등록)**:
- 결함 A: valuein pre-fetch `betrayed` 는 줄어든다(2026-09-23 진단 — 배신 10건 중 9건이 결과 밖 파일을 열지 않았다).
  단 셸로 결과 밖 파일을 읽은 턴이 새로 배신이 되므로 순감소 크기는 예측하지 않는다.
- 결함 B: 인용 채택은 0 보다 크다. 크기는 예측하지 않는다.
- 무변동 예상: `tool` 레인의 Grep 도구 기반 배신, `find`/`fd` 기반 배신.

**하지 않는 것**: 채택 기준치 설정, 판정 결과로 정의 수정(수정이 필요하면 v1.3 으로 새로 등록), 외부 판정 API.
